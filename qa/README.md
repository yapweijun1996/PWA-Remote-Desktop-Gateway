## Approved current-Mac view-only pilot

`npm run test:local-mac-view` is a separate test-classpath-only harness for an owner-approved Mac with existing Screen Sharing. Supply `RDG_LOCAL_VNC_SECRET_FILE` as an absolute path to an existing owner-only VNC password file outside Git; never include the password itself in a command, chat or log. The harness requires the recorded local official-source guacd image identity and does not pull/build it. It publishes only a temporary guacd port on 127.0.0.1 for the local Java test process; the fixed server-owned VNC target is `host.docker.internal:5900`, referring to the current Mac from Docker Desktop. Its HTTPS edge is loopback-only. It removes only its own processes, container, certificate, signed assertion and temporary state. The supplied credential file remains owner-controlled.

This harness uses an ephemeral RS256 test identity with the normal JWT/session/CSRF/Origin boundaries. Production `Config.load` and the production JAR remain unchanged; unknown modifier keysyms are left empty only in the view-only test configuration. The test connector rejects control or clipboard before opening upstream. The browser uses view mode and saves no screenshots, desktop text, clipboard, keystrokes or tunnel payload. Results go to `implementation/local-mac-view-results.json` as metadata only. A live view pass proves narrower local VNC/display/cleanup interoperability, not real Cloudflare issuance, keyboard calibration, control or public release. Do not start it without owner approval for that Mac.

`npm run test:vnc-security` uses the exact image identities recorded in the artifact ledger and a network-none synthetic RFB peer. It sends no password challenge, credentials or pixels. Its five policy cases cover ARD/None preference, unsupported-only refusal and legacy3.3 None rejection. This is authentication-selection/deny-path evidence, separate from the actual-Mac view test.

## Bounded native diagnostic collector

For an already approved local-view investigation, build the test-only syslog interposer with `./qa/build-native-vnc-diagnostics.sh`, then run `./qa/test-native-vnc-diagnostics.sh`. The compiler is reused only by its reviewed immutable ID in `native-vnc-diagnostics-builder.json`; no compiler package install or production image mutation occurs. These commands run synthetic cases and the real official-daemon unreachable-target flow with network disabled and no credentials. A missing reviewed compiler is a prerequisite failure; do not substitute a mutable image tag.

Set `RDG_LOCAL_VIEW_NATIVE_DIAGNOSTICS=true` only for that approved view test. The exact production image mounts the digest-checked interposer read-only. It discards every unknown native message and writes only a closed list of fixed labels to a bounded 0600 file on the container's private tmpfs. No raw native logs, server reasons, pixels, passwords or payloads are saved. The host capture validates Docker exit status and has a ten-second child deadline; missing/read-failed metadata is unavailable and cannot be merged as COMPLETE. Capture occurs while the owned daemon still exists, without a Docker attach stream. The default view harness does not load the logger. `RDG_LOCAL_VIEW_OUTPUT` is honored for metadata output.

A generic failure label or absence of an authentication label leaves the cause UNKNOWN. Even SERVER_REPORTED_AUTHENTICATION_FAILURE is the server's assertion, not proof that the supplied password was wrong. No guessed retry, Keychain access or host-settings change follows from diagnostic output. Task-created temporary credentials must be deleted after the run; the harness preserves owner-supplied files.
