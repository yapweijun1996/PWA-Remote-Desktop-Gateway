# Synthetic bandwidth benchmark

Run `sh qa/bandwidth-benchmark.sh` after the production gateway JAR has been built. This test uses the reviewed exact local guacd and Java image IDs in `qa/implementation/artifacts.json`; it never pulls an image. It compiles the separate QA helper and mounts only its generated classes into a disposable client container. The official Java Guacamole library negotiates with the actual pinned daemon. The client and synthetic VNC peer share the daemon's network-none namespace and communicate through fixed loopback ports only. No published port, live gateway, Mac desktop, credential file, Tunnel or host setting is used.

The helper compares Low (16-bit color and lossless Guacamole output), Balanced (unchanged daemon defaults) and Clear (24-bit color and lossless Guacamole output). It compiles an immutable snapshot of production `DisplayQuality.java` with the QA helper and reads its parameters through that class's actual `parse`/`apply` methods. The final validator checks both the production-source hash and all three selected parameter maps, preventing silently duplicated presets. Each profile runs three times for two explicitly synthetic server capabilities: Raw only, and Zlib/Raw. The latter selects the first supported encoding actually requested by guacd. The current default encoding list excludes Tight, and the fixture rejects an unexpected Tight advertisement. Neither a new Tight decoder path nor VNC JPEG payload is exercised. It uses an eight-character disposable test password in memory to satisfy the existing password-authentication policy, not a real user's credential.

Each run sends the same deterministic 640×360 animated gradient/noise pattern, with one initial frame followed by 12 full-frame changes triggered by synthetic pointer messages. The peer honors the negotiated pixel format and, for Zlib only, the observed compression pseudoencoding. The client acknowledges official Guacamole frame synchronization and image streams. The fixture checks frame/pointer correlation and negotiated 16/24-bit depth before accepting a result. Raw-only targets ignore compression settings by design. Color reduction remains effective, while upstream compression benefits depend on the target's actual selected encoding. A flat desktop, scrolling text, video or high-resolution display will produce different byte counts. Low uses reduced 16-bit colors; it is unsuitable for judging photographs or precise colors.

The JSON report contains counts and timing metadata only. Pixel bytes, base64 blobs, desktop text, pointer coordinates, authentication challenge/response and protocol payloads are never logged or saved. All processes and both owned containers are removed on success/failure; the Java and outer shell have finite 90/120-second deadlines. Production containers are neither inspected for content nor restarted.

Interpret the measurements precisely:

- RFB download/upload counts cover actual synthetic TCP payload bytes, including initialization/authentication and 13 frames. RFB image payload counts exclude rectangle headers.
- Guacamole download/upload counts cover actual client TCP payload bytes after the initial frame. Encoded image and base64 byte counters separately measure the image streams. These exclude WebSocket framing, TLS, HTTP and Cloudflare overhead. They are not internet wire-byte counts.
- KiB/s is the throughput of this sequential synthetic local workload. It is not a bandwidth limit or WAN network capacity estimate. Compare bytes for the same 12 frames when assessing the profiles.
- The synthetic pointer-to-frame-sync median/p95 includes frame generation/compression, loopback transfer and guacd processing. It excludes actual operating-system input delivery, Mac rendering, browser rendering and WAN round-trip time. First-frame latency is measured independently from library handshake completion.
- `force-lossless` applies to daemon-to-client graphical encoding. It cannot restore detail discarded by a VNC server's lossy encoding.

Results are written atomically to `qa/implementation/bandwidth-20261004/synthetic-benchmark.json`. The helper's `candidate8`, `candidate16lossless` and `candidate8lossless` modes each run one preliminary Low override with Zlib; these are experiment records, not three-profile acceptance. Earlier rejected 16/8-bit candidates are retained separately. Production compression-level and JPEG-quality overrides were removed because 1.6.0 assigns them after `rfbInitClient` has sent the initial encoding preferences; the observed compression pseudoencoding remained 3 in the 16-bit baseline despite requested 9/6. No native implementation is patched. This test does not establish real Mac/Cloudflare/internet bandwidth or click-to-visible-response latency. The browser's in-memory payload counters and Guacamole sync estimate provide separate real-session observations; real action-to-render acceptance remains a manual gate.

Official protocol/configuration references: [Apache1.6.0 VNC settings source](https://raw.githubusercontent.com/apache/guacamole-server/1.6.0/src/protocols/vnc/settings.c), [Guacamole VNC configuration](https://guacamole.apache.org/doc/gug/configuring-guacamole.html#vnc), and [LibVNCServer0.9.14 RFB definitions](https://raw.githubusercontent.com/LibVNC/libvncserver/LibVNCServer-0.9.14/rfb/rfbproto.h).

Release 1.2.2 restores a 16-bit Low preset after a real approved-Mac comparison: 8-bit returned upstream error 515 while 16-bit, Balanced and Clear streamed. Historical 1.2.0 synthetic byte savings do not establish compatibility or savings for this replacement. Compare current real-session counters; no lower browser bandwidth is guaranteed.
